# 実行環境を記録する

対象プロジェクトで実際に使う環境と、そこへ入る方法を再利用できる形にする。診断だけの依頼では、確認結果を報告し、指示ファイルを自動追加しない。

- 既存の AGENTS.md / CLAUDE.md、起動スクリプト、flake.nix、.envrc、pyproject.toml、package.xml などから対象環境を絞る。すべての環境を列挙・起動する必要はない。
- 対象環境でコマンドの実体、バージョン、必要なパッケージを確認する。ホストにないことと、実行環境にないことを区別する。
- 指定があればそのファイルを更新する。指定がなければ既存の環境説明を更新し、どちらもなければ AGENTS.md に記録する。CLAUDE.md が必要なら参照で共有し、説明を二重管理しない。
- 記録には、用途と環境、作業ディレクトリ、source するファイルや起動方法、検証コマンド、実際に観測した結果を含める。
- 環境名、ROS ディストリビューション、Python、モデルのパスを推測で固定しない。汎用例のプレースホルダーをそのまま実行しない。
- 検証は対象環境で行う。ビルド、ノード起動、実機入力のうち何を確認したかを分ける。機器がない場合はその制約を記録する。
- 実機の移動やデバイス書き込みなどを、環境確認のためだけに追加しない。指定された作業範囲と権限内で確認する。
