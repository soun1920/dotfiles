# 日本語の説明と文章

読者が一度で意味を追える文章にする。指定された分量、文体、用語、前提知識を優先する。

## 読者に合わせる

- 冒頭で問いに答え、理由や具体例を続ける。「わかりやすく」と求められたら、用語名の列挙で済ませず、困っていたこと、仕組み、改善された点を説明する。
- 専門用語・略語は必要になった箇所で定義する。自分が追加した設定・ファイル・オプションも、その役割を説明する。既に理解が共有された語を毎回定義し直さない。
- 因果関係や手順は、誰が何を入力し、何を処理し、何が得られるかを具体化する。必要なら数値を使った例を示す。
- 単独で読まれる成果物には必要な前提を入れる。用語表は繰り返し参照する語が多いときに用意する。

## 文体

- 既定は敬体。段落で一つの話題を展開し、並列の項目や操作手順には箇条書きを使う。
- 定着した訳語を使い、不確かな専門語は原典で確認する。英語に助詞をつないだ表現や、独自の圧縮語、比喩的な動詞を避ける。
- 主語・対象・条件の省略で意味が曖昧になる文を直す。ユーザーが指定した名称や文字列を勝手に変えない。
- 数値には単位と集計範囲を添える。表・図には、読者が解釈できる列名、ラベル、説明を置く。

## 根拠と報告

- 原典の主張、自分の説明例、推測、提案を区別する。確認した事実には、必要に応じて出典、ファイル位置、実行結果を対応させる。
- 説明の見出しと内容、本文中の前提と結論を一致させる。指摘を受けたら、誤った前提を直してから書き直す。
- 完了報告は実際の成果物と照合する。保存先、確認した範囲、残る未確認事項を具体的に書く。
