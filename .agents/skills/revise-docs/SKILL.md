# 原稿一式の推敲

1. 先に `~/.agents/skills/japanese-tech-writing/references/exemplars-prose.md` を読み、次に同じディレクトリの `SKILL.md` を読む。目指す文体は手本にあり、条項は違反の検出にだけ使う。
2. 編集前に `git status` で、同じディレクトリを別のセッションが編集中でないか確かめる。変更済みのファイルがあれば、それを報告してから進める。
3. 対象ファイルをすべて全文読む。正規表現だけの走査で済ませない。
4. 対象が4ファイル以上なら、編集前に次の表を出して承認を待つ。3ファイル以下ならそのまま進めてよい。

   | ファイル | 見つかった問題 | 具体的な修正 |

5. 3ファイルずつ編集し、そのたびにビルドを通す。`mkdocs.yml` があれば `mkdocs build --strict`、`main.typ` があれば `typst compile main.typ`。失敗したら次の3ファイルに進む前に直す。
6. 報告は読者の視点でファイルごとにまとめる。自分の試行錯誤の経過は書かない。
