# 原稿一式の推敲

依頼された範囲の意味と技術的正確さを保ち、読者が追える文章へ直す。

- 指定された文体と既存の原稿を優先する。共通の日本語規範は [ja-text-communication](../ja-text-communication/SKILL.md) を使う。
- 著者の文体を合わせる必要がある場合は、指定された実物の手本を読む。特定の文体 skill が未導入・無効でも、既存の原稿と利用可能な規範で進める。
- git/yadm の差分と対象ファイルを確認し、変更済みの内容を保持する。これだけでは同時編集の不存在を証明できないため、適用直前の内容と照合する。
- 対象ごとに文脈を読み、意味のまとまりで編集する。大きな依頼では対象・完了済み・残りを記録し、固定のファイル数で承認待ちにしない。
- 共通用語・参照・構造に関係する修正は利用箇所も確認する。全文の置換だけで推敲を済ませない。
- 既存のビルド方法に従って結果を確認する。節目や構造変更後に検証し、同じ小変更のたびに全体を再ビルドする必要はない。
- 依頼による不具合は直す。以前からの失敗や環境制約は分けて報告し、関係のない修正へ広げない。
- 完了した対象、変更の要点、検証結果、残る対象を報告する。
